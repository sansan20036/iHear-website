### Stopping failure and read-only triage

Test: `tests/impact-admin.spec.mjs:635`,
`Resources show verified form links, localized descriptions and a private management entry`.

At line 641, the test expected three resource list entries but received zero after
5 seconds. The first six tests (published first-paint content in three languages)
passed. Playwright then stopped at the configured first failure. The runner also
reports one error outside a test; its original output is retained without
relabeling the run as passing or inferring a separate cause.

The preserved trace confirms `GET http://127.0.0.1:3210/api/resources` returned HTTP
200 with three Items and two Topics, but **no `guidesTakeover` property**. The mock
response is produced by `resourceSnapshot()` at `tests/impact-admin.spec.mjs:626`.
That helper returns only `topics` and `items`.

The accepted Checkpoint 6 renderer in `assets/resources.js:64` requires an explicit
`guidesTakeover` value of `legacy` or `complete`. Missing state is intentionally
rejected with `Guide takeover state unavailable`; the render path therefore shows
no resource items. This directly explains the observed result without assuming
that production data is missing or that a database request failed.

Classification: **E2E mock/API contract mismatch**, not a newly proven production
data loss or application defect. The mock's pre-takeover contract needs review
against the current API. No fixture, assertion or application logic was changed,
and no successful corrective rerun is claimed. The same helper is referenced by
other unexecuted Resources tests, which remain unverified.
