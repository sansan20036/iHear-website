# 錄影上傳 Pathway：Google 測試環境與驗收程序

> **狀態：程序與工具已備妥，並已在本機用模擬環境完整演練通過；Google 端尚未建立任何東西。**
> 標示「需授權」的步驟，要等您明確同意後，由帳號擁有者本人在瀏覽器操作。
>
> 測試期間有三條規則：
> - 只用合成資料。
> - 不碰老師提供的正式錄影資料夾。
> - 不啟用正式錄影上傳，也不切換為 `live`。

| 項目 | 狀態 |

| A5 以合成資料測試 | 方向已核准，A4 確認後才開始上傳 |

## 1. 測試環境長什麼樣子

```
測試擁有者帳號（新的免費 Google 帳號，只用於測試）
├─ [測試] 錄影上傳表單（Google 表單，含檔案上傳題）
│    └─ 表單自動建立的上傳資料夾（由 Forms 管理）
├─ [測試] 錄影上傳紀錄（Google 試算表，連結表單回覆）
│    └─ Apps Script：Core、Code、appsscript.json，加上 3 個觸發器
├─ [測試] iHear 錄影存放區（目的地資料夾，一般存取權「限制」）
│    ├─ _待確認（程式自動建立）
│    └─ [iHear] 09.2026.Zoom Recordings、[iHear] 10.2026.Zoom Recordings（TC-05 自動建立）
└─ 防呆測試（非測試資料夾）（空資料夾，只在 TC-24 用）

小老師角色：由測試擁有者帳號本身填表上傳合成影片（不使用任何日常帳號）
```

## 2. 怎麼確保碰不到真實錄影

| 層次 | 做法 | 防的是什麼 |
|---|---|---|
| 帳號隔離 | 所有東西都建在新的測試帳號；這個帳號沒有老師資料夾或任何真實錄影的存取權 | 就算程式有錯，Google 也不會讓它存取真實錄影 |
| 測試模式（預設） | `MODE` 預設為 `test`：目的地資料夾名稱必須以「[測試]」開頭，學生代碼必須以「TEST-」開頭，不符合就暫停所有處理 | 設定填錯，例如貼了正式資料夾 ID 或真實名單 |
| 表單只限測試帳號回覆 | 發布表單時，回覆者存取權設為「限制」，不加入任何人；只有測試擁有者能填答 | 其他人即使拿到連結，也無法上傳 |
| 只處理本表單的檔案 | 每次搬移或改名前，先向表單確認這個檔案確實屬於某一筆回覆 | 目的地資料夾原有的檔案不會被動到；手動填進紀錄的檔案 ID 也不會被處理 |
| 刪除前核對 | 移到垃圾桶前，核對位置、檔名和 MD5 是否都和紀錄相符 | 已被改名、搬走或替換的檔案不會被刪 |
| 程式本身不會做的事 | 不改分享設定、不永久刪除、不讀檔案內容、不列出整個雲端硬碟 | 由本機自動測試逐行檢查，以後改程式也會擋下 |

## 3. 所需帳號、Google 權限與成本

### 帳號

| 角色 | 需要什麼 | 建議 |
|---|---|---|
| 測試擁有者 | 一個 Google 帳號，免費 Gmail（15 GB）即可 | 新建一個帳號，名稱由您決定。不要使用可以存取老師資料夾的帳號 |
| 小老師角色 | 上傳檔案必須登入 Google | 由測試擁有者帳號本身填表。**不得使用您的日常帳號或老師的帳號**，而且只上傳合成影片。上傳後的檔名可能會附加填表帳號的顯示名稱，詳見 TC-01 |
| 通知收件人 | 一個信箱 | 用測試擁有者的信箱 |

### Apps Script 會要求的 6 項權限

這 6 項寫在 `appsscript.json`，由測試擁有者本人授權。

| 權限 | 用途 | 注意 |
|---|---|---|
| `spreadsheets.currentonly` | 讀寫這份綁定的試算表（設定、名單、紀錄） | 只限這一份試算表 |
| `forms` | 讀取表單回覆、檢查題目、同步下拉選單 | 可以存取擁有者所有的表單，所以要用測試帳號 |
| `drive` | 搬移、改名、建立子資料夾、讀取 MD5、檢查分享設定、讀取用量、移到垃圾桶 | 這是 Google 的「受限範圍」，能存取擁有者看得到的所有雲端硬碟檔案。表單上傳的檔案不是程式建立的，所以無法縮小成 `drive.file`。這也是一定要用測試帳號的主要原因 |
| `script.scriptapp` | 建立和刪除觸發器 | |
| `script.send_mail` | 寄異常通知 | 免費帳號每天最多 100 位收件人 |
| `script.container.ui` | 試算表裡的選單與提示 | |

### A3：授權畫面（確認後才按允許）

在 S5 第一次執行 `prepareSheets` 時，會依序出現以下畫面：

1. 編輯器的「需要授權」對話框：點「審查權限」。
2. 選擇帳號：只能選**測試擁有者帳號**。如果出現其他帳號，表示瀏覽器設定檔不對，請按取消。
3. 「Google 尚未驗證這個應用程式」：個人或測試用的 Apps Script 要求敏感權限時，這是正常畫面。點「進階」，再點「前往（不安全）」。這一步還不會授予任何權限。
4. 權限清單：Google 現在允許逐項勾選。畫面上應該**剛好**是下列 6 項。英文介面的說明如下，中文介面的措辭可能略有不同：

   | 權限 | 畫面上的說明（英文介面） |
   |---|---|
   | `spreadsheets.currentonly` | View and manage spreadsheets that this application has been installed in |
   | `forms` | View and manage your forms in Google Drive |
   | `drive` | See, edit, create, and delete all of your Google Drive files |
   | `script.scriptapp` | Allow this application to run when you are not present |
   | `script.send_mail` | Send email as you |
   | `script.container.ui` | Display and run third-party web content in prompts and sidebars inside Google applications |

**第一次走到權限清單時：截圖後按「取消」，不要按「繼續」或「允許」。** 按取消不會授予任何權限。

您確認後，再執行一次並勾選全部 6 項。如果少勾任何一項，程式會停止並再次要求授權（使用 `ScriptApp.requireAllScopes`）。這是為了避免程式在權限不完整時照常執行；例如沒有寄信權限，就會發生寄不出通知卻沒人發現的情況。

只有擁有者一人需要授權。小老師只是填表單，不會執行也不會授權這個程式。

### A4：觸發器明細（確認後才在 S11 安裝）

| 觸發器 | 頻率 | 操作目標 | 會做什麼 |
|---|---|---|---|
| `onFormSubmit` | 每次有人送出測試表單 | 只限「[測試] 錄影上傳表單」那一筆回覆所附的檔案 | 登記到「上傳紀錄」，把檔案從表單上傳資料夾搬到「[測試] iHear 錄影存放區」並改名；不符規定的移到 `_待確認` |
| `processQueue` | 每 15 分鐘 | 「上傳紀錄」中待處理或失敗未達上限的列，以及測試表單最近 14 天漏登的回覆 | 重試與補登，目標同上一列 |
| `dailyReport` | 每天 22:00–23:00 之間一次 | 已存放的檔案（只讀取名稱、位置、是否在垃圾桶）與帳號用量 | 在「每日核對」加一列；有異常時寄信給 `ADMIN_EMAILS` |

**觸發器的範圍與限制**
- 三個觸發器都以測試擁有者的身分執行。
- 測試模式下，只要目的地不是「[測試]」資料夾，或名單有代碼不是 `TEST-` 開頭的學生，就全部暫停。
- 觸發器不會修改分享設定、不會永久刪除、不會讀取檔案內容。
- 移到垃圾桶只會在您手動執行「移除已確認到期錄影」時發生。

**停止方式（任選一種）**
1. 試算表選單 →「停用自動處理（移除觸發器）」：立即移除 3 個觸發器。
2. Apps Script 編輯器左側的「觸發條件」頁面：逐一刪除。
3. 到 myaccount.google.com/permissions 移除這個專案的存取權：之後的執行一律失效。
4. 把表單設為不再接受回覆：之後不會再有新的上傳。

**不需要：**
- 自行建立 Google Cloud 專案、API 金鑰或服務帳戶；
- 任何付費方案；
- 修改 Vercel、資料庫或 Zoom。

1. 產生合成影片。需要 ffmpeg，約 15 秒：

   ```
   node tools/recording-pathway/test-env/make-test-media.mjs
   ```

   檔案會放在系統暫存資料夾的 `ihear-recording-test-media`（Windows 是 `%TEMP%\ihear-recording-test-media`），刻意不放在 OneDrive 裡。

   - 每次重新產生的檔案都逐位元組相同。暫存資料夾就算被系統清掉，重新產生後 MD5 比對也不受影響。

## 6. 建立測試環境

步驟分成三段，中間有兩個確認關卡：

| 階段 | 步驟 | 條件 |
|---|---|---|
| 第一段 | S0–S4：建立帳號、資料夾、表單、試算表，貼上程式 | A1、A2 已核准 |
| A3 關卡 | S5 第一次執行：只擷取授權畫面並按取消，交給我核對 | 等您確認 |
| 第二段 | S5–S10：完成授權、設定與名單。此時還沒有任何觸發器 | A3 確認後 |
| A4 關卡 | 確認第 3 節的觸發器明細 | 等您確認 |
| 第三段 | S11：安裝觸發器，接著跑第 7 節的驗收案例 | A4 確認後 |

**S0　建立測試帳號（A1，由您本人操作）。**

1. 在 Chrome 新增一個專門給測試帳號用的「設定檔」（右上角頭像 →「新增」）。同一個瀏覽器同時登入多個 Google 帳號時，Apps Script 可能用錯帳號執行；分開設定檔可以避免這個問題。
2. 在新的設定檔開啟 https://accounts.google.com/signup ，選「建立帳戶」→「供個人使用」。
3. 姓名請用與真人無關的名稱，例如「iHear Recording Test」，不要用老師或學生的姓名。
4. 生日等必填欄位，依 Google 的要求填寫帳號持有人的資料。Gmail 地址自選，例如含有 `ihear` 和 `test` 的名稱。
5. 密碼請存在您的密碼管理工具，不要傳給任何人，包括我；整個流程都不需要密碼。Google 若要求手機驗證，依畫面完成即可；復原信箱可以設成您自己的信箱。
6. 這個帳號**不要**接受任何真實資料夾的共用、**不要**上傳任何真實檔案，也**不要**連結到其他服務。

**小老師角色：** 由測試擁有者帳號本身填表。**不得使用您的日常帳號。** 小老師看不到存放區這一點（TC-23），改用未登入的視窗驗證。

**S1　建立資料夾。** 登入測試擁有者帳號，在雲端硬碟建立兩個資料夾，一般存取權都是「限制」：
- `[測試] iHear 錄影存放區`
- `防呆測試（非測試資料夾）`

把兩者網址中 `folders/` 後面的 ID 記下來。

**S2　建立表單「[測試] 錄影上傳表單」。**

設定 →「回覆」：

| 項目 | 設定 |
|---|---|
| 收集電子郵件地址 | 已驗證 |
| 允許編輯回覆 | 關閉 |
| 限制只能回覆一次 | 關閉 |

題目名稱必須和下表**完全相同**，否則程式會暫停並告訴您缺哪一題：

| # | 區段 | 題目 | 題型與設定 |
|---|---|---|---|
| 1 | 1 | 上課日期 | 日期，必填，包含年份 |
| 2 | 1 | 學生 | 下拉選單，必填。選項在 S9 由程式同步 |
| 3 | 1 | 小老師 | 下拉選單，必填 |
| 4 | 1 | 本堂是否錄影 | 選擇題，必填。選項是「有錄影」「整堂未錄影」，並開啟「依答案前往區段」：有錄影 → 區段 2；整堂未錄影 → 區段 3 |
| 5 | 2 | 錄影檔 | 檔案上傳，必填。只允許「影片」「音訊」，檔案數上限 10，**單檔上限先設 10 MB**（TC-14 會改成 1 GB）。區段 2 結束後提交表單 |
| 6 | 3 | 未錄影原因 | 段落，必填。區段 3 結束後提交表單 |

第一次加入檔案上傳題時，Google 會提示檔案會存到擁有者的雲端硬碟，按確認即可。

**發布並限制回覆者。** 按右上角的「發布」，在管理回覆者的設定中：
- 回覆者的存取權選「限制」；
- 不新增任何人：只有測試擁有者本身可以填答；
- **不要**選「知道連結的任何人」。

發布後的填寫連結不傳給任何人。介面文字可能略有不同；如果您的表單沒有「發布」按鈕，而是「傳送」，請先截圖給我，再決定替代做法。

**S3　連結試算表。** 在表單的「回覆」分頁選擇連結到試算表，建立新的試算表，命名為「[測試] 錄影上傳紀錄」。

**S4　貼上程式。** 在試算表點「擴充功能」→「Apps Script」：
1. 在「專案設定」勾選「在編輯器中顯示 appsscript.json」。
2. 把預設的 `程式碼.gs` 改名為 `Code`，貼上 [`../apps-script/Code.js`](../apps-script/Code.js) 全文。
3. 新增指令碼 `Core`，貼上 [`../apps-script/Core.js`](../apps-script/Core.js) 全文。
4. 把 `appsscript.json` 的內容換成 [`../apps-script/appsscript.json`](../apps-script/appsscript.json)。
5. 儲存。

檔案的先後順序不影響執行。「服務」底下應該會自動出現 Drive API。

1. 在試算表切到「上傳紀錄」分頁，選「檔案」→「下載」→「逗號分隔值 (.csv)」。
2. 執行：

   ```
   node tools/recording-pathway/test-env/check-acceptance.mjs "<下載的 CSV 路徑>"
   ```

   程式會讀第 5 節產生的 `manifest.json`，逐案判定 PASS 或 FAIL，並做 5 項整體檢查：

   | 編號 | 檢查內容 |
   |---|---|
   | G1 | 名單只有合成資料 |
   | G2 | 每個檔案的 MD5 都是本機產生的合成檔 |
   | G3 | 沒有重複登記或重複存放 |
   | G4 | 沒有殘留待處理或失敗的列 |
   | G5 | 各資料夾彼此分開 |

   它也會列出 CSV 無法判斷、需要人工記錄的項目。

3. **通過標準：**
   - 檢查程式全部 PASS；
   - 所有「必做」的人工項目都符合預期；
   - 沒有來源不明的列。

4. **要保存的證據（都只含合成資料）：**
   - CSV 和檢查程式的輸出；
   - 截圖：
     - S5 的授權畫面

     - 通知信清單
     - TC-15 的「執行作業」
     - TC-22 和 TC-23 的權限畫面

## 9. 收尾與清除（A7）

1. 選單 →「停用自動處理（移除觸發器）」。
2. 把表單設為不再接受回覆。
3. 決定測試資源要保留，留作日後改程式時的回歸測試環境；或刪除以下項目並清空垃圾桶：
   - 表單
   - 試算表
   - `[測試]` 資料夾
   - 表單自動建立的上傳資料夾
4. 如果不再使用，到 myaccount.google.com/permissions 移除這個 Apps Script 的存取權。
5. 本機的合成檔資料夾可以直接刪除。

以上步驟都不會碰到老師的資料夾。
