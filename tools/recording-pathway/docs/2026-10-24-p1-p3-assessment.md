# P1 錄影安全規範與 P3 線上教室 MVP 評估（2026-10-24）

對象：iHear 負責人與 Justine 老師。

範圍：
- 只整理規範與做技術查證；
- 沒有處理任何真實學生錄影；
- 沒有建立帳號、憑證或付費資源；
- 沒有修改正式網站或資料庫。

## 先讀這裡

1. **自動雲端錄影的前提：每一組都要有自己的教室。**
   - Zoom 分組教室只能由房內的人用電腦版本機錄影，雲端錄影只涵蓋主會議室（P1 已查證）。
   - Zoom Video SDK 的子會議能不能各自錄影，官方文件沒有說明。
   - 所以 MVP 採「一組一間教室」：一位小老師帶自己的學生，每間各自錄影、各自歸檔。
2. **技術選型建議：Zoom Video SDK，並以 Daily 作為備案。**
   - Zoom Video SDK：搭配官方現成的網頁介面元件（UI Toolkit），在網站內建教室。
   - 功能面：七項需求已依官方文件確認可行；只有手機和平板上的瀏覽器無法分享螢幕。
   - 費用面：Zoom 沒有公開確切費率，必須先建立免費的開發者帳號，在後台確認。
   - 備案：Daily。若 Zoom 的錄影儲存費用不合理，改用 Daily。費用已由官方價格頁確認，架構完全相同。
3. **P1 的自動歸檔邏輯可以直接重用。**
   - 用合成資料在本機驗證過六種情境，全部通過（第 4 節）。
   - 重用的部分：命名、分段、同意檢查、重複防護、異常隔離。
   - 換掉的只有「表單上傳」這個入口。
4. **試用前一定要先完成的，是 P1 的規範決策，不是程式。**
   - 規範：家長同意、誰能看、保存多久、能不能暫停。
   - 法律確認：學生有未成年人，包括美國 13 歲以下的兒童。

## 1. P1：錄影安全規範待決事項

「建議」欄是我的提案，需要你和 Justine 老師決定；涉及法律的部分，建議再請專業人士確認。

### 1.1 錄影同意與未成年學生保護

| # | 待決事項 | 建議 |
|---|---|---|
| 1 | 由誰同意 | 由家長或法定代理人簽署書面同意。依台灣個資法函釋，父母可以代未成年子女行使同意權。同意必須在充分告知後才有效，而且由 iHear 負舉證責任 |
| 2 | 美國學生 | 英文課程頁招收國際學生。若有美國 13 歲以下的學生，COPPA 修訂版要求取得「可驗證的家長同意」，並且必須有書面的資料保存政策與資安計畫，保存政策要公開在隱私權聲明中（2026-04-22 起必須遵守）。錄影不在「只錄聲音」的例外範圍內 |
| 3 | 告知內容 | 錄影目的（教學品質、家長回顧，以及是否用於導師培訓）、錄哪些內容（影像、聲音、分享的畫面）、保存多久、誰能看、如何撤回 |
| 4 | 同意紀錄 | 名單中標記「已同意」，並記錄日期和同意書版本。家長撤回後，從下一堂課起不再錄影；已有的錄影是否刪除，需要另外決定 |
| 5 | 未同意的學生 | 沿用 P1 規則：課程照常進行，但整堂不錄。群組課中只要有一人未同意，整堂就不錄 |
| 6 | 學生本人 | 年紀較大的學生，建議也讓本人知道上課會錄影 |
| 7 | 法律確認 | 建議請律師確認台灣與美國的要求，以及同意書的文字 |

### 1.2 存取權限與保存期限

| # | 待決事項 | 建議 |
|---|---|---|
| 8 | 誰可以看錄影 | 只限 iHear 指定的管理員。小老師不能下載。家長申請觀看時，由管理員依流程提供 |
| 9 | Drive 資料夾 | 一般存取一律設為「限制」。P1 程式偵測到資料夾公開或任何知道連結的人都能看時，會停止處理並通知管理員 |
| 10 | 存放錄影的帳號 | 使用組織專用帳號，並開啟兩步驟驗證，不放在個人帳號，避免帳號遺失或交接時的單點風險 |
| 11 | 保存天數 | 需要決定（P1 的 `RETENTION_DAYS`，正式使用時必填）。例如 90 天；到期後由管理員確認，才會移到垃圾桶 |
| 12 | 視訊服務端的暫存檔 | 錄影成功存入 Drive 並核對無誤後，就刪除 Zoom 或 Daily 雲端上的副本。建議在 72 小時內完成 |

### 1.3 預設錄影的告知與控制

| # | 待決事項 | 建議 |
|---|---|---|
| 13 | 何時開始錄影 | 小老師進入教室後，伺服器先確認「本堂所有學生都已同意」，才自動開始雲端錄影，所以不會因為忘記而沒錄。只要有一人沒有同意，就不啟動錄影，畫面上會顯示原因 |
| 14 | 告知方式 | 進入教室前顯示「本堂課會錄影」。上課中，錄影標示一直顯示在畫面上。Zoom 也建議在產品中提供錄影告知 |
| 15 | 暫停與停止 | 需要決定小老師可以暫停、繼續或停止錄影的權限。建議小老師可以暫停，系統記錄暫停的時間，整堂停錄則需填寫原因（沿用 P1 的「整堂未錄影」規則） |

### 1.4 雲端錄影完成後的自動命名與分類

- **檔名：** 沿用 P1 的格式 `YYYY-MM-DD_學生_小老師_P01.mp4`。
  - 建議改用學生代碼（`NAME_MODE=code`），檔名就不會出現學生全名。
  - 群組課有兩種做法，需要決定：用 `+` 連接每位學生的代碼（本機驗證採用這個做法），或另外給每個班級一個代碼。
- **分段：** 錄影暫停後再繼續，會變成 `P01`、`P02` 等多段。
- **資料夾：** 每月一個子資料夾，例如 `[iHear] 11.2026.Zoom Recordings`。
- **只保留一種檔案：** 只保留「分享畫面加講者」這一種合成影片；音訊檔和逐字稿是否保留另外決定。
- **異常處理：** 未同意、不在排程上的教室、重複的檔案，都會隔離到 `_待確認` 並通知管理員。通知只寫列號和狀態，不含學生姓名。
- **紀錄：** 每個檔案記錄一列，包括狀態、原始檔案編號和存放位置。MVP 可以先沿用試算表，之後再改用資料庫。

### 1.5 原 Google 表單方案可以重用的部分

| 可以重用（`tools/recording-pathway/`） | 需要更換 |
|---|---|
| `Core.js` 的命名、分段、學生代碼、同意檢查、每月資料夾、設定檢查。本機驗證時直接載入，**沒有修改任何一行** | 表單上傳入口，改成接收錄影完成通知 |
| 狀態設計：`STORED`、`DUPLICATE`、`NO_CONSENT`、`RETENTION_DAYS` 到期、`TRASHED` 等 | 用來確認檔案確實來自本表單的檢查，改成驗證通知的簽章與上課排程 |
| 安全限制：不修改分享設定、不永久刪除、移到垃圾桶前三項條件都要符合 | 表單名單同步 |
| 每日核對、容量警示、測試模式防護、模擬 Google 環境的測試工具 | 小老師本機錄影和上傳的操作說明 |

另外，P1 原型的 `tools/` 資料夾目前**沒有被 Git 追蹤**（從未 commit）。建議先在本機 commit，避免遺失。

TC-28 依指示維持未完成。

### 1.6 P1 怎麼落地：讓小老師不用手動上傳

- **原方案做不到：** 原本的 Google 表單方案，一定要小老師手動上傳，因為 Zoom 分組教室只能本機錄影。Justine 老師的新要求必須改用**雲端錄影**。
- **前提：** 每一組各自是一場會議，或各自是一間教室。
- **兩種做法：** 存進 Drive 這一段完全相同，都重用 `Core.js`。

| | 做法一：沿用 Zoom，每組各開一場會議 | 做法二：等 P3 的網站內建教室 |
|---|---|---|
| 運作方式 | 系統透過 Zoom API 替每組建立會議：全員已同意就設定自動雲端錄影，否則不錄。錄影完成後，系統收到通知，自動命名並存進 Drive | 見第 5 節 |
| 小老師要改的習慣 | 不再開分組教室，每組直接進自己的會議連結 | 改用網站上的教室 |
| 需要的費用 | 每組同時上課都要一個 Zoom 付費授權 | 依使用量計費 |
| 開發時間（核准後） | 約 1–2 週 | 約 3–4 週 |

**建議：** 如果 Justine 老師希望盡快停止手動上傳，就先採用做法一，P3 再接著做。兩者共用存進 Drive 的程式，所以不會白做。

**做法一需要的核准：**
1. 第 1.1–1.4 節的規範決策；
2. 確認目前的 Zoom 方案與授權數量；
3. 建立 Zoom 的 Server-to-Server OAuth 應用程式，用來排課和接收錄影完成通知；
4. 第 6 節的 E（Drive 授權）與 F（Vercel 方案）。

Zoom 會議 API 的自動錄影設定（`settings.auto_recording`）和錄影完成通知（`recording.completed`），正式串接前要再對照官方文件確認。

## 2. P3：Zoom Video SDK 需求對照

| # | 需求 | 結論 | 依據與限制 |
|---|---|---|---|
| 1 | 電腦、平板、手機 | 可行 | 電腦用瀏覽器。手機和平板的瀏覽器也可以使用：iOS 16.4 以上、Android Chrome 112 以上，橫向時可以傳送 720p。另有原生 iOS 和 Android SDK |
| 2 | 攝影機、麥克風、教材、螢幕分享 | 大致可行 | 視訊與音訊都可以。電腦版 Chrome 和 Edge 可以分享分頁、視窗或整個螢幕，分享分頁時可以帶分頁的聲音。**手機和平板的瀏覽器無法分享螢幕**，所以要分享教材的小老師必須用電腦。白板功能官方沒有說明，教材以分享畫面為主 |
| 3 | 多間獨立教室與分組 | 可行 | 每間教室就是一個 session，加入時的憑證決定角色，小老師是主持人。官方也支援子會議，一場最多 50 個，由主持人管理；但子會議能不能錄影沒有說明，所以 MVP 不使用 |
| 4 | 取得同意後自動錄影 | 可行 | 伺服器可以用 REST API 送出 `recording.start`；主持人的程式也可以在加入時呼叫 `startCloudRecording()`，並且可以暫停、繼續、停止。網頁版最高錄到 1080p。同意的把關由我們的伺服器負責 |
| 5 | 自動存進 Google Drive | 可行，需要伺服器 | 錄影完成時 Zoom 會送出 `session.recording_completed` 通知，再用 API 取得下載連結，由伺服器分段上傳到 Drive。命名與分類邏輯已在本機驗證。需要考慮的部署限制：Vercel 函式在 Hobby 方案最長 300 秒、Pro 方案最長 800 秒，一堂課的錄影約 200–750 MB，所以要分段上傳或改用背景工作 |
| 6 | 成本 | **尚未確認** | 見第 3 節。必須先有 Video SDK 帳號，並購買 Cloud Recording Storage Plan |
| 7 | MVP 範圍與時程 | 見第 5 節 | — |

## 4. 本機可行性驗證（合成資料）

程式：`planning/p3-recording-dryrun/dryrun.mjs`。它用合成的上課排程和名單，模擬 Zoom 格式的錄影完成通知，並直接載入 P1 的 `Core.js`。全程不連網路、不使用任何憑證，Drive 那一步只會印出「將要做什麼」。

| 案例 | 結果 |
|---|---|
| 1 一堂課中途暫停一次（兩段影片加一個音訊檔） | 存成 `[iHear] 11.2026.Zoom Recordings/2026-11-03_TEST-S01_陳小老師_P01.mp4` 和 `P02`，音訊檔不保留 |
| 2 同一個通知再送一次（重送） | 判定為 `DUPLICATE`，不會重複存檔 |
| 3 通知內容在簽章後被竄改 | `REJECTED`，簽章不符 |
| 4 10 分鐘後再送一次（重放） | `REJECTED`，時間戳記過期 |
| 5 群組課中有一位學生未同意 | `NO_CONSENT`，隔離到 `_待確認` |
| 6 不在排程上的教室 | `HOLD`，不存任何檔案 |

結果：`DRY RUN: PASS (all six cases)`。

通知的欄位名稱是依官方說明推估的。正式串接前，要再和 Zoom 的參考文件逐一對照。

## 5. MVP 計畫

### 5.1 最小功能範圍

- **教室頁：**
  - 每堂課一個加入連結，由排課產生，小老師和學生各自取得自己的連結；
  - 進入前顯示錄影告知與同意狀態；
  - 介面使用 Zoom 官方的介面元件，提供視訊、聲音、聊天和分享螢幕。
- **自動錄影：**
  - 小老師進入教室後，伺服器確認所有學生都已同意，才開始錄影；
  - 錄影標示一直顯示在畫面上，小老師可以暫停和繼續。
- **自動歸檔：**
  - 依序完成接收通知、驗證、下載、分段上傳到 Drive、套用 P1 的命名與分類、寫入紀錄；
  - 核對無誤後，刪除視訊服務端的副本。
- **管理員：**
  - 建立教室，也就是排課；
  - 查看錄影紀錄，並處理 `_待確認` 裡的檔案。
- **不做：** 付款、完整的學習平台、逐字稿和字幕（第二階段）、原生 app。
- **資料庫：** 需要新增教室、錄影紀錄、同意紀錄三張表。這要等 P2 上線後，照同一套 migration 程序進行。
- **測試環境：** Preview 和正式環境共用資料庫的問題還沒解決，所以 P3 的測試不能使用 Preview。

### 5.2 預估時程

一位開發者，核准能在幾天內完成：

| 週次 | 內容 |
|---|---|
| 第 0 週（2–3 天） | 取得核准、建立帳號，在 Zoom 後台確認費率。若費率不合理，就切換到 Daily |
| 第 1 週 | 本機原型：教室頁、角色、同意把關，使用合成的媒體串流和測試帳號 |
| 第 2 週 | 自動錄影和錄影完成通知，以及串到 Drive 的流程，用合成教室做端對端測試 |
| 第 3 週 | 排課、處理紀錄、錯誤處理、安全檢查，並在電腦、iPad、Android 和 iPhone 上實測 |
| 第 4 週 | 向 Justine 老師和小老師說明操作，然後試用 2–3 堂課。必須在同意書完成、你另行核准後才開始 |

結論：約 **3–4 週**可以開始小規模試用。法律審閱需要的時間不包含在內。
