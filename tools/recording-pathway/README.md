# iHear 錄影上傳 Pathway（原型）

小老師在 Zoom 分組教室用電腦版錄影，課後透過 Google 表單上傳。之後 Apps Script 會自動：

- 依「上課日期＋學生＋小老師」改名
- 把檔案放進指定的 Google Drive 資料夾
- 在試算表記下每個檔案的處理結果

## 目前狀態

| 項目 | 狀態 |
|---|---|
| 本機 | 已用合成資料和假影片測試，含整個驗收程序的模擬演練 |
| Google 測試環境 | 程序與工具已備妥，見 [`test-env/README.md`](test-env/README.md)；尚未在 Google 建立任何資源 |
| 正式上線 | 依 [`GO-LIVE.md`](GO-LIVE.md) 逐步取得授權 |

## 流程

```
Zoom 分組教室（小老師用電腦版本機錄影，可暫停或不錄）
  → 課後填「錄影上傳」Google 表單（日期、學生、小老師、檔案；或回報「整堂未錄影」）
  → Apps Script（表單送出時執行；每 15 分鐘重試，並補登觸發器漏接的回覆）
      1. 檢查設定、表單題目，以及資料夾是否對外分享
      2. 確認檔案確實來自本表單的回覆
      3. 檢查檔案類型
      4. 檢查錄影同意
      5. 檢查是否重複上傳
      6. 先把標準檔名記進紀錄
      7. 搬到目的地資料夾並改名
      8. 核對結果
  → 「上傳紀錄」試算表（每個檔案一列：狀態、嘗試次數、說明）
  → 每日核對（找出被手動改名、搬走或丟進垃圾桶的檔案，並回報雲端硬碟用量）
```

標準檔名的格式是 `2026-10-23_王小明_陳小老師_P01.mp4`。同一堂課的第二段錄影是 `P02`，以此類推。

## 程式絕對不做的事

以下由本機自動測試逐行檢查，以後修改程式也會被擋下：

- 不修改任何分享設定
- 不永久刪除檔案
- 不讀取或下載檔案內容
- 不列出整個雲端硬碟

它只搬移、改名或刪除**透過本表單上傳的檔案**。目的地資料夾裡原本就有的檔案，以及手動填進紀錄的檔案 ID，都不會被處理。移到垃圾桶前，必須同時符合三個條件：

1. 管理員在該列填了「是」；
2. 檔案的位置與檔名都和紀錄相同；
3. 檔案的 MD5 也和紀錄相同。

## 哪些是自動的，哪些要人工

| 步驟 | 方式 | 說明 |
|---|---|---|
| 開分組前開放錄影權限 | 人工（主持人） | 對每位小老師點「允許錄影」，必須在開分組前完成 |
| 分組教室開始、暫停、停止錄影 | 人工（小老師） | Zoom 只支援在分組教室裡用電腦版本機錄影，無法遠端替各房間自動錄影 |
| 不錄影 | 人工 | 小老師不按錄影，課後在表單選「整堂未錄影」並填原因 |
| 上傳檔案 | 人工（小老師） | 填表單並附上檔案，需要登入 Google 帳號 |
| 改名、歸檔、記錄、防止重複、重試、補登漏接的回覆 | 自動 | Apps Script |
| 沒有錄影同意、檔案類型錯誤、重複的檔案 | 自動隔離，人工處理 | 檔案移到 `_待確認` 並通知管理員。處理完畢後，把該列狀態改成 `HANDLED`；要重新處理，就改回 `RECEIVED`，並把嘗試次數改為 0 |
| 每日核對 | 自動 | 每天 22:00 執行，包含雲端硬碟用量警示 |
| 保存期限到期 | 自動標記，人工刪除 | 管理員在該列「確認刪除」填「是」，並且檔案核對相符後，才會移到垃圾桶 |
| 修改目的地資料夾 | 人工（管理員） | 修改「設定」分頁的 `DEST_FOLDER_ID` |
| 暫停或恢復自動處理 | 人工（管理員） | 選單「停用自動處理」或「啟用自動處理」 |

## 設定（試算表「設定」分頁）

執行 `prepareSheets`（只授權並建立分頁，不裝觸發器）或「啟用自動處理」（`setup`）時，程式會自動補上缺少的設定列和說明。這兩步分開，所以授權（A3）和安裝觸發器（A4）可以各自確認。

| 設定項目 | 預設 | 說明 |
|---|---|---|
| `MODE` | `test` | 詳見下方「測試模式」 |
| `DEST_FOLDER_ID` | （必填） | 目的地資料夾 ID。修改後只影響新上傳的檔案。測試期間只能填 `[測試]` 資料夾，正式上線前不要填老師的資料夾 |
| `MONTHLY_SUBFOLDER` | `off` | 設為 `on` 時，依上課月份放進 `[iHear] MM.YYYY.Zoom Recordings` 子資料夾 |
| `NAME_MODE` | `full` | 設為 `code` 時，檔名用「學生名單」裡的學生代碼取代姓名 |
| `RETENTION_DAYS` | （空白） | 保存天數。留白代表尚未決定，不會標記任何到期檔案；正式模式必填 |
| `MAX_ATTEMPTS` | `5` | 每個檔案最多自動重試幾次 |
| `ADMIN_EMAILS` | （空白） | 接收異常通知的信箱，正式模式必填。通知只寫列號和狀態，不含姓名；同一個設定問題一天最多通知一次 |
| `STORAGE_WARN_PERCENT` | `80` | 雲端硬碟用量達到這個百分比時通知管理員 |
| `TEST_FAULT` | （空白） | 僅限測試模式：填 `move`、`rename` 或 `md5`，會讓處理在該步驟故意失敗，用來驗收重試與通知 |

**測試模式（`MODE=test`）**

- 目的地資料夾名稱必須以「[測試]」開頭，學生代碼必須以「TEST-」開頭，否則暫停處理。
- 通知信主旨會加上「[測試]」。
- 要改成 `live`（正式模式）必須先取得授權，見 [`GO-LIVE.md`](GO-LIVE.md)。

**分享設定**：目的地資料夾若設為公開、知道連結的任何人或機構內可見，處理會暫停並通知管理員。程式**不會**自動修改分享設定。

## 狀態

| 狀態 | 意思 |
|---|---|
| `RECEIVED` | 已收到，等待處理 |
| `STORED` | 已改名並放進目的地 |
| `FAILED` | 處理失敗，會自動重試；達到上限後通知管理員 |
| `DUPLICATE` | 內容和已存放的檔案相同，或同一個檔案被重複登記，已隔離 |
| `NO_CONSENT` | 學生名單沒有「已同意」，已隔離並通知管理員 |
| `INVALID` | 不是 mp4、m4a、mov；表單內容有誤，例如日期不存在或在未來；或檔案不是透過本表單上傳 |
| `NOT_RECORDED` | 小老師回報整堂未錄影 |
| `RETENTION_DUE` | 已超過保存期限，等待管理員確認刪除 |
| `TRASHED` | 已移到 Drive 垃圾桶，30 天內可救回 |
| `HANDLED` | 管理員已人工處理完畢，不再列入每日核對 |

## 本機測試

```
node --test tools/recording-pathway/test/pathway.test.mjs tools/recording-pathway/test/acceptance.test.mjs
```

### `test/fake-google.mjs` 模擬的情況

- 試算表把日期、數字自動轉型
- Drive 允許同名檔案並存
- 搬移、改名、取得 MD5、寄信失敗
- 表單觸發器重複或漏接
- 資料夾被公開分享
- 同時有其他程序在處理
- Apps Script 先載入 `Code.js`

### `test/acceptance.test.mjs` 做的事

- 依 `test-env/README.md` 的順序，在模擬環境跑完整個驗收程序；
- 再用測試人員實際會用的同一支程式（`check-acceptance.mjs`）判定結果。

### 驗收工具

| 工具 | 用途 |
|---|---|
| `node tools/recording-pathway/test-env/make-test-media.mjs` | 用 ffmpeg 產生合成影片 |
| `node tools/recording-pathway/test-env/check-acceptance.mjs <上傳紀錄.csv>` | 檢查從 Google 下載的紀錄 |

## P3 線上教室（合成原型）

之後錄影改由每堂課的獨立雲端教室自動產生，P1 的命名規則（`Core.js`）照樣使用。這部分目前只有設計和合成原型：沒有連到 Zoom，也還沒放進網站。

| 位置 | 內容 |
|---|---|
| [`docs/`](docs/) | 交接規格、管理員即時教室總覽、失敗處理規則、Zoom 帳號查核、MVP 驗收清單 |
| `classroom/` | 入場與錄影資格、webhook 持久化與歸檔、課程狀態、總覽（都是純函式） |
| `dryrun/` | `recording-webhook.mjs`（命名示範）、`live-dashboard.mjs`（2、5、10 堂同時上課的模擬） |

全部測試：`node --test "tools/recording-pathway/test/*.test.mjs"`
