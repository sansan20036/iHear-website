# 多人教室真實服務驗收（V-1～V-17、D-1、D-2）

這份文件給執行驗收的工程人員和 iHear 帳號持有人。它說明三件事：

- 哪些項目在本機已經用模擬（Fake API、本機瀏覽器）驗證過；
- 哪些還要真實的 Zoom 或 Google Drive 才能驗證；
- 怎麼操作。

本機通過只證明我方的邏輯正確，不能代替真實驗收。兩種結果分開記錄，不合併計算。

本 repo 是公開的，任何帳號資訊、金鑰、資料夾 ID 都不寫進這裡。

## 1. 分類

| 分類 | 意思 |
|---|---|
| Fake API 已驗證 | 我方送出的請求、對回應的處理、安全規則，已經用假的 Zoom／Google API 驗證過 |
| 本機瀏覽器已驗證 | 頁面行為已經用本機瀏覽器加上模擬的 Zoom SDK 驗證過 |
| 待真實 Zoom | Zoom 本身的行為（事件、延遲、權杖範圍、錄影）要用真實帳號才看得到 |
| 待真實 Drive | Google Drive 本身的行為（權限、既有資料夾、上傳）要用真實測試帳號才看得到 |
| 需 iHear 帳號持有人操作 | 需要帳號持有人建立憑證、核准雲端錄影或費用，或提供裝置 |

每一項的分類、本機證據和真實驗收步驟，都寫在 `v-items.mjs` 裡。

## 2. 本機部分（隨時可以跑，不連外）

```
node tools/classroom-acceptance/run.mjs --list    # 列出各項目與分類
node tools/classroom-acceptance/run.mjs --local   # 執行本機證據，寫出 output/acceptance/v-items.{json,md}
npm run test:classroom:multi-browser              # 本機瀏覽器（E1～E14，含換房後提供恢復裝置、第二分頁）
```

`--local` 會用 JSON 報表跑一次各項目引用的 vitest 測試，另外跑 recording-pathway 的 node 測試（webhook 去重、歸檔）。輸出時：

- 本機證據全部通過的項目，標示「合成通過（本機）」；
- 真實驗收的狀態一律標示「未驗證」。

## 3. 真實部分（要先取得核准；本工具不會連線）

`node tools/classroom-acceptance/run.mjs --real` 只會拒絕，並提示你回到這一節。

開始之前，以下條件都要成立：

1. **帳號與費用：** iHear 帳號持有人已經核准 Video SDK 帳號、API Key／Secret 和雲端錄影。費用一律標示「等待 iHear 費用授權」，不可自行購買或開啟付費功能。
2. **只用測試身分和 `TEST-` 代碼：**
   - 不用學生資料；
   - 不用日常帳號；
   - 不用任何老師或 iHear 工作人員的真實帳號或資料夾。
3. **憑證放在 repo 之外：**
   - 不讀、不印出設定檔的內容。
   - 要確認設定是否齊全，只用各工具的 `--check`，它只列出名稱。
4. **緊急停止：** 先確認緊急停止可以用（`tools/classroom-recording-test/emergency-stop.mjs`）。

### 建議順序（照 2026-11-09 的 Zoom 驗收計畫）

| 步驟 | 內容 | 項目 | 需要錄影？ |
|---|---|---|---|
| Z0 | 只做唯讀的 REST GET，不開 session | V-3 | 否 |
| Z1 | 兩個測試身分開 session，收 webhook | V-1、V-2、V-4、V-6、V-7、V-15、V-17 | 否 |
| Z2 | 錄一段 TEST- 課程（需要另外核准） | V-5、V-10、V-11、V-13、V-14、D-1 | 是 |
| Z3 | 測試端點故意回 503 | V-9 | 依 Z2 |
| Z4 | 各種裝置的換房與手機 | V-8 | 否 |
| Z5 | 2 間同時錄影（5 間和 10 間要另外核准） | V-16 | 是 |
| G1 | Drive：測試帳號的既有資料夾、Picker、權限政策 | D-2 | 否 |

可以使用的工具：

- **`tools/classroom-trial/`：** 試用伺服器和通道，不錄影。
- **`tools/classroom-recording-test/`：** 只在本機執行。必須加上 `--real-recording`，而且要有帳號持有人的核准。

### 每一項要記錄什麼

- 日期時間（美東時間和台北時間）、執行人、核准來源；
- 使用的測試代碼；
- 原始回應碼和事件的時間；
- 是否符合 `v-items.mjs` 寫的通過條件。

另外有兩條規則：

- 結果分開記在「真實」欄，絕不覆寫本機欄。
- 不符合的項目要寫明影響範圍，例如：
  - V-8 換房太慢時，改變分房的操作方式；
  - V-15 能跨房時，必須另外設計權限邊界，不能上線。

## 4. 不在範圍

- **V-12 `user.remove`：** D-3 決定不申請。移出教室改用兩個做法：伺服器停止發放 token，加上頁面自動離開。
- **5 間或 10 間同時錄影、真實學生、正式網站：** 都需要另外核准。
